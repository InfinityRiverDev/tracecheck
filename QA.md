## Приёмка финальной React/Redux-версии (#14)

Проверки web/ подтверждают только эталон. Новая client/ требует отдельной проверки после #11–#13:

- Прямой вход на каждый маршрут и возврат на главную.
- Полный набор улик открывает вывод; одиночная адресная правка оставляет связь, две адресные правки или удаление подписи убирают её.
- Перезагрузка восстанавливает выбор улик, правки и ответы, отчёт пересчитывается.
- Ответы visible/hidden/unknown дают объяснимо разные результаты; без ответа нет завершённой оценки.
- Сброс очищает обе ветки и только ключи TraceCheck, результат сохраняется после перезагрузки.
- Повреждённое или устаревшее сохранение не ломает интерфейс; запрет storage допускает прохождение в памяти.
- Телефон 360 px и ПК: без горизонтальной прокрутки и перекрытия кнопок, видимый фокус, подписи полей.
- Локальное прохождение не отправляет ответы на сервер. Серверный режим проверяется отдельно после явного выбора пользователя.

Ожидается стабильный client/ от исполнителей #11–#13.

## API HTTP (#15)

Исходный main 6d5371e: npm test — 19/19, npm run build — успешно.

При ревью найдены и исправляются в qa/http-hardening:

- Некорректный request target мог вызвать необработанное отклонение Promise; разбор URL перенесён внутрь обработки ошибок, ответ 400.
- Проверка static пути по строковому префиксу допускала соседние dist-* каталоги; заменена проверкой относительного пути.
- Невалидный PUT без объекта state мог стереть прогресс или вернуть 500; теперь 400 без save.
- Первый временный сбой подключения MongoDB кэшировался навсегда; отклонённое подключение сбрасывается для следующей попытки.

Проверки выполняются на loopback с fake store, без реальной БД и чтения секретов. Финальный результат записывается после прогона регрессий.

Результат #15: npm test — 34/34 успешно, включая HTTP регрессии некорректного URL, encoded traversal, payload и повторную инициализацию MongoDB. Изменения подготовлены в отдельной ветке qa/http-hardening.

## #14 — восстановление Redux и быстрый F5

Валидируются ID улик/правок/выводов, уникальность списков, ID вопросов и вариантов ответа. Пустые ответы не позволяют восстановить done=true; позиция возвращается к первому незаполненному вопросу и ограничена длиной анкеты. Состояние сохраняется синхронно после dispatch, чтобы немедленный F5 не терял последнюю правку. Reset возвращает обе ветки к пустому состоянию.

Добавлены 12 тестов Redux/loaders/store без DOM; отдельная регрессия проверяет чтение сохранения немедленно после dispatch без ожидания таймера. Общий результат npm test: 55/55. Production build после изменений slices/store прошёл.
